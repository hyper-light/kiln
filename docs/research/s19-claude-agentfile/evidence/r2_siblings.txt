## Step 25's unpacker: git log -1 a04cffd0
a04cffd0cd0ffb72c8807437ad49181dfe826c5f 2026-11-12T01:35:11-08:00
tar.gz unpacking for the Agentfiles' context fetcher (kiln plan 01a1ce705e4d7008993f5c7291ef4476, step 2)

agentfiles::unpack::tar_gz unpacks a gzip tar whose size and SHA-256 have matched its pin into a
harness's per-arch directory: every entry into a fresh directory inside it, each header checked
before tar writes anything; then the top-level entries renamed into place, never over a name already
there; then the directories given their modes in place, deepest first; then the archive removed.
Only directories and regular files are taken, at relative paths without `..` and without set-ID bits.
Links, devices, FIFOs and every other kind refuse the archive, naming the entry:
Unpack { url, entry, why: Link | Device | Escapes | SetId | Kind | Io }. tar 0.4.46's own unpack_in
strips a leading `/`, skips `..`, makes links and writes devices and unknown kinds as regular files,
so each check is kiln's. Directories stay writable until they're placed, since Linux moves a
read-only directory to another parent for no one but root (rename(2), EACCES). On failure nothing
it made is left, nor the archive. No marker is written beside the entries (f26).

Decided by step 25's coordinator, overriding the step's text, which said set-ID and sticky bits are
cleared: set-ID bits refuse the archive (SetId), as pin.sh and Shards' check of an artifact refuse
them, and modes are kept as pinned. The sticky bit is never applied (mode & 0o777). FIFOs are
Device; Kind(typeflag) names any other kind; pax and GNU metadata headers are passed over by name.

Step 19's fetcher isn't committed yet, so its hook, the HTTP light-integration test and the live
context wait for it. Devin's two pinned bundles (3000.12.43) hold 234 regular files and 16
directories each, and nothing else (their raw headers: docs/research/s25-devin-agentfile/evidence/).
macOS arm64 (Mac Studio, kiln run r10): the module's 5 tests pass. clippy -D warnings on
-p kiln --all-targets reports one error, step 30's (an unused import in agentfiles/tests.rs), none
