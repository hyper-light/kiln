     1	# kiln, for coding agents
     2	
     3	kiln is one Rust binary: a CI/CD server, a deployer (Argo CD's model), a fleet of runners, and
     4	the front end for coding agents (Claude Code, Codex, ACP agents, Antigravity, Devin), with its
     5	web UI embedded. Read this before you change it, then the documents it points to.
     6	
     7	## The rules
     8	
     9	`docs/ci.md` §0 holds the rules for every line written here; §0.3 binds. In short:
    10	
    11	- **No panics.** The workspace denies `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!`,
    12	  `unreachable!`, unchecked indexing and `exit` (`Cargo.toml`). Bad input becomes an error value
    13	  shown to the person, never a crash.
    14	- **hyper-rt, not tokio.** Async code runs on hyper-raft's `hyper-rt`; HTTP is kiln's own
    15	  (`crates/kiln-http`, `docs/http.md`). Don't add tokio, hyper, h2, axum, reqwest, kube-rs or
    16	  tokio-rustls. If hyper-rt lacks something, say so and ask.
    17	- **Deterministic cores.** Logic that decides lives in `crates/kiln-ci` and `crates/kiln-cd` as
    18	  pure code: no clock, disk, network or randomness except what's passed in.
    19	- **SQLite is CI's system of record**, changed only by numbered migrations
    20	  (`crates/kiln/src/store/migrations`).
    21	- **The protocol only grows.** `crates/kiln/src/proto.rs` is postcard by variant index: new
    22	  variants go after every existing one, and new capabilities are new bits.
    23	- **General hardware.** Pick machines by what they can do, never by name.
    24	- **The UI** (`ui/`): the hyperlight-site style; one primary surface per page; no popups
    25	  (modals, sheets, floating panels); no effects (`useEffect` is a lint error; data comes through
    26	  Suspense); static by default; a press never waits on the server to show it was taken (W21-R15:
    27	  `ui/src/lib/action.ts`); checked in Chromium and WebKit at desktop and phone widths.
    28	- **Opt-in automation.** What kiln decides on its own is off until declared, and says why it did
    29	  what it did.
    30	- **Seams.** kiln reaches other products only through `crates/kiln-seams` (`docs/seams.md`):
    31	  each seam is a trait, a simulator and a conformance suite.
    32	- **Change only what the task asks for.** Mention any other improvement instead of making it.
    33	
    34	## IDs
    35	
    36	- `Wnn-Rmm` and `Wnn-ACmm` are `docs/ci.md`'s requirements and acceptance criteria.
    37	- `CP-T3.2`, `AC-T1.4.2`, `T-T2.1.1` and the like come from kiln's critical-path program. Its

    44	## Hazards
    45	
    46	- **Never restart, swap, upgrade or reinstall a runner** (`kiln install`, `kiln join`, replacing
    47	  `~/.local/bin/kiln`, its LaunchAgent or its service). Agents run through runners, likely you
    48	  among them, and a restart ends their sessions. Say what the upgrade is; the person does it.
    49	- **Production runs on adacachy, beside other work.** Heavy builds and tests go where kiln puts
    50	  them, never to a machine by name: ask for what they need (`kiln run --needs`, or MCP `run` with
    51	  `needs`). Your change's gate (below) holds each of its runs to what it asked and yields to
    52	  production. Anything else heavy: `nice -n 10` and your own `CARGO_TARGET_DIR`.
    53	- **Big files go under `~/.cache`, never `/tmp`.** On the Linux machines `/tmp` is a RAM disk
    54	  every session shares.
    55	- **Stop only what you started,** by the PID you recorded as you started it. Never `pkill -f` or
    56	  `pgrep -f`: other sessions run the same commands.
    57	- **No tree-wide `cargo fmt`.** kiln's long lines aren't rustfmt's; clippy is the check. For UI
    58	  files, run `npx prettier --print-width 200 --write` on the files you changed, and only those.
    59	- **Wire formats change append-only:** postcard variants, capability bits, new JSON fields
    60	  optional.
    61	- **Never print or commit a secret,** kiln's admin token included.
    62	- **The person's word** is needed for every merge to main, every push and every deploy, and to
    63	  create a repository. Deploys go through KilnCD, in merge trains (`docs/trains`).
    64	- **Git:** never a bare `git stash`; rebase and squash only onto a fixed SHA; every push waits on
    65	  the exit codes of the tests relevant to its change.
    66	
    67	## Your change's gate
    68	
    69	You compose it, not kiln. `ci/gate.sh` runs one step alone (`clippy`, or `test`; both when neither
    70	is named), natively where it runs, on the crates you name, held to what its run asked for.
    71	
    72	- **Scope:** `--since origin/main` takes the crates your change touches (committed or not), those
    73	  whose code reads a file it changed by path (a test reading a doc or `.kiln/`: string literals,
    74	  not comments) or builds a changed crate by path, and every crate depending on them. A changed
    75	  file in no crate that none reads puts the whole workspace in scope.
    76	  `ci/gate.sh --since origin/main --dry-run` says which and why; `-p <crate>` adds one.
    77	- **Platforms:** clippy on Linux, macOS and Windows, each natively; tests on Linux, and on macOS or
    78	  Windows too where your change has code for them.
    79	- **Side by side:** `ci/gates.sh` starts a run per platform at once, each through `kiln run --needs`
    80	  with the CPUs (`<N>`) and memory (`<M>`) its steps need, waits for each and keeps its output:
    81	  ```sh
    82	  ci/gates.sh --needs linux/amd64,cpus=<N>,mem=<M> --since origin/main \
    83	              --needs macos,cpus=<N>,mem=<M> clippy --since origin/main \
    84	              --needs windows,cpus=<N>,mem=<M> clippy --since origin/main
    85	  ```
    86	  Never detach a gate's run or leave it to a bare `wait`: either exits 0 whatever the run said.
    87	- **Sized** by measurement, never a picked number: a step runs a rustc per CPU asked, is capped at
    88	  the memory asked, and runs nothing without both. Each step says its peak memory (on Linux its
    89	  anonymous memory, page cache left out; on macOS its processes' resident memory; on Windows
    90	  none): ask that next time. Measured so far: kiln's own crate takes 7 GiB and more to build, and
    91	  the libraries' tests peaked at 16.7 GiB at `-j 4` (`.kiln/ci.yaml`).
    92	- **One verdict:** each run ends `GATE: PASS`; `GATE: FAIL` and why; or `GATE: YIELDED` (exit 75:
    93	  it stopped for a strained machine; run it later or elsewhere). `ci/gates.sh` passes only when
    94	  every run exited 0 and said `GATE: PASS`.
