A harness.json's run.env sets its harness's HOME and PATH: init's defaults give way, the last given winning; SHARDS_DOMAIN stays init's

init gave a supplied domain PATH, HOME=/tmp and SHARDS_DOMAIN, then appended run.env without
removing duplicates. Go and glibc's getenv read the first, so no harness.json could set HOME or
PATH; agentfile's startup test already reads run.env HOME=/state, the meaning intended. Found by
the agy Agentfile's agent (kiln plan 01a1cd8e862e7169a074db3d5fa33f3d, steps 26 and master 7):
agy, which has no config-dir variable of its own, wrote its config under init's HOME.

- init's harness_env merges by name, the last given winning, and looks the program up on the PATH
  the domain runs with.
- SHARDS_DOMAIN, a domain's own name, is refused in run.env at build (osi::Config::check, what
  every reader checks) and at run (init), as D231's staging refuses it.
